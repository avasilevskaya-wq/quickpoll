# Как запустить QuickPoll (≈15 минут, один раз)

Нужно сделать две вещи:

1. Google-таблица, куда будут падать ответы (5–7 минут).
2. GitHub Pages: там будет жить сама страница (5 минут).

Программировать ничего не нужно, только копировать и нажимать кнопки.

---

## Шаг 1. Google-таблица для ответов

1. Откройте **https://sheets.new**. Создастся новая таблица, назовите её, например, «QuickPoll — ответы».
2. В меню таблицы: **Расширения → Apps Script** (*Extensions → Apps Script*). Откроется редактор кода.
3. Удалите всё, что там написано, и вставьте целиком содержимое файла **`apps-script/Code.gs`** из этого проекта. Нажмите 💾 (Сохранить).
4. **Выдайте разрешения.** Вверху в выпадающем списке функций выберите `authorize` и нажмите **▶ Выполнить** (*Run*).
   - Появится «Требуется авторизация» → **Проверить разрешения** → выберите свой аккаунт.
   - Google покажет «Приложение не проверено». Это нормально: это ваш собственный скрипт. Нажмите **Дополнительные настройки → Перейти на страницу … (небезопасно) → Разрешить**.
5. **Опубликуйте как веб-приложение.** Справа вверху **Начать развертывание → Новое развертывание** (*Deploy → New deployment*).
   - Нажмите ⚙ рядом с «Выберите тип» → **Веб-приложение** (*Web app*).
   - *Запуск от имени:* **Я** (*Execute as: Me*).
   - *У кого есть доступ:* **Все** (Anyone). Это важно: иначе заказчик не сможет отправить ответ.
   - **Развернуть** (*Deploy*) → скопируйте **URL веб-приложения** (*Web app URL*) (он заканчивается на `/exec`).

> ⚠️ Если пункта «Все» нет, значит, ваш корпоративный Google Workspace запрещает публичные скрипты. Сделайте шаги 1–5 под личным Gmail-аккаунтом.

**Письма на почту** приходят на адрес аккаунта, под которым создан скрипт. Другой адрес можно указать в строке `NOTIFY_EMAIL = ''` в начале скрипта.

**Если потом поменяете код скрипта:** **Начать развертывание → Управление развертываниями → ✏️ → Версия: Новая версия → Развернуть** (*Deploy → Manage deployments → ✏️ → Version: New version → Deploy*). URL останется прежним.

---

## Шаг 2. Страница на GitHub Pages

1. Зайдите на **github.com** → справа вверху **+ → New repository**.
   - *Repository name:* например, `polls`. Адрес страницы будет `https://ВАШ_ЛОГИН.github.io/polls/`.
   - Выберите **Public**: бесплатные GitHub Pages работают только с публичными репозиториями. Секретов в коде нет.
   - **Create repository**.
2. На странице нового репозитория нажмите ссылку **uploading an existing file**.
3. Распакуйте архив `quickpoll.zip` и перетащите в окно браузера **всё содержимое папки**: `index.html`, `config.js`, папки `assets`, `s`, `apps-script` и остальные файлы. Перетаскивайте сами файлы и папки, а не папку `quickpoll` целиком. Внизу нажмите **Commit changes**.
4. Откройте **Settings → Pages** (слева в меню).
   - *Source:* **Deploy from a branch**.
   - *Branch:* **main**, папка **/ (root)** → **Save**.
5. Подождите 1–2 минуты и обновите страницу. Вверху появится ссылка вида `https://ВАШ_ЛОГИН.github.io/polls/`. Это ваш конструктор.

---

## Шаг 3. Соедините страницу с таблицей

**Вариант А (быстрый):** откройте конструктор → ⚙ (Настройки) → вставьте URL из шага 1 → **Check** → должно появиться «Connected ✓» → **Save**.
Настройка запомнится только в этом браузере.

**Вариант Б (навсегда, для любого браузера):** на GitHub откройте файл `config.js` → ✏️ (Edit) → вставьте URL между кавычками:

```js
window.QP_CONFIG = {
  endpoint: 'https://script.google.com/macros/s/ВАШ_КОД/exec'
};
```

→ **Commit changes**. Через минуту конструктор будет знать адрес в любом браузере, а ссылки на опросы станут короче.

---

## Шаг 4. Проверка (2 минуты)

1. В конструкторе: **+ New → Quick approval** → **Get link** → **Open**.
2. Ответьте на опрос и нажмите **Send answers**.
3. В таблице появится новая вкладка с ответом, а на почту придёт письмо.

Готово 🎉

---

### Если что-то не работает

| Симптом | Что сделать |
|---|---|
| «Couldn't reach the script» при проверке | URL должен заканчиваться на `/exec`. В развертывании должен быть доступ «Все». |
| Ответ отправился, но в таблице пусто | Скорее всего, код скрипта меняли без нового развертывания: нужна **Новая версия** (см. шаг 1). |
| Страница на GitHub показывает 404 | Подождите пару минут. Проверьте, что `index.html` лежит в корне репозитория, а не во вложенной папке. |
| Не приходят письма | Проверьте папку «Спам». Gmail даёт до 100 писем в день. |
